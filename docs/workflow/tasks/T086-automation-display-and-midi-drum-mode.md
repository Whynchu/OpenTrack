# T086 - Focused automation lanes and MIDI drum mode

- Status: in_progress
- Scope version and requirement IDs: 1
- Desired observable outcome: Project automation controls show and edit one selected automation target at a time per track. The MIDI editor offers Piano Roll and Drum Map modes over the same selected part and notes. Drum Map mode uses named pitch rows and beat-centered diamond hit markers; it does not present duration as the visible/editable hit shape.
- Reference evidence (IDs/paths; observed vs user-specified vs unknown): User direction (2026-11-03): the automation field under each track should show only the selected automation type; Drum Editor should be an option inside the MIDI editor, switching between piano-roll notes and named drum-hit rows. Drum hits are snapshots, represented by a diamond whose center aligns to the beat. Existing `app/drum_editor.rs` is a separate window over MIDI notes; `core::drum_map::DrumMap` stores project row names/order, and existing Drum Map Setup supports user-authored maps. MT Power Drum Kit 2.1.5.1 Linux VST3 is a user-selected real-instrument test target, not a layout/parity target; vendor lists Reaper, Ardour, Bitwig and Carla as tested hosts. The 60.9 MB x64 package was extracted and inspected, then installed under the user's `~/.vst3`; all listed shared-library dependencies resolved on Ubuntu 26.04 x86_64. The isolated OpenTrack scanner enumerated one `MT-PowerDrumKit` Instrument class with zero rejected modules. A full in-app instance/audio/editor test did not complete because OpenTrack stalled during window navigation before instantiation. Vendor package EULA limits distribution and isolated sample use; the test uses the local plug-in only and will not redistribute plug-in binaries or samples.
- Dependencies and decisions needed: Existing MIDI notes remain the source of truth and retain their MIDI timing, duration, velocity, channel, playback, and interchange behavior. Drum mode visually treats note-on beat as the hit center and hides duration editing. Ship General MIDI percussion as a selectable map preset; preserve current custom/identity map behavior. Automation target selection is view/workspace state, not a project-content edit; default to Volume and do not hide, delete, or rewrite stored automation lanes.
- Code scope and architecture boundaries: Project track automation-row UI and per-track focused target state; MIDI editor toolbar/view mode and shared lower-zone renderer; drum-map preset data and selector using existing core map validation. Keep domain map data and event identity in `opentrack-core`; rendering and view selection in app. No changes to note playback or project schema unless required by demonstrated persistence constraints. Remove/retire the standalone drum-editor window once its useful interactions are integrated.
- Acceptance checks (action, expected result, fixtures, evidence to retain):
  1. Choose Volume, Pan, Mute, Send, or supported plug-in target for a track; only that target's automation lane/value editor is shown and edits/read/write affect that target. Other stored targets remain intact.
  2. Save/reopen workspace preferences: selected visible target and MIDI editor mode restore without dirtying project content. Project automation and note content round-trip unchanged.
  3. Switch the selected MIDI part between Piano Roll and Drum Map in the MIDI editor; selection and note identity remain shared. Switching views changes presentation only.
  4. Load the General MIDI percussion map and a custom map; mapped row names/order appear, unmapped pitches remain accessible with numeric fallback, and changing maps never transposes notes.
  5. Drum hits render as diamonds with their centers on the note-on beat; snapped insertion/movement places the hit center on the selected grid. Duration is not shown or resized in this mode; velocity, deletion, selection, playback, and MIDI export remain functional.
  6. Undo/redo, dirty state, and save/reopen remain correct for actual note/map content edits; view switching and automation target selection create no project-history entries.
  7. With MT Power Drum Kit loaded on Linux, test mapped kick/snare/hat notes and verify note-on pitch/beat, velocity response, audible output, save/reopen state, and plug-in editor lifecycle. Record any host-specific failure separately from drum-map behavior.
- Affected regressions: Project automation lane height/hit testing and focused-target edits; MIDI editor toolbar, lower-zone sizing, note selection/undo, snap, map setup and persistence; MIDI playback/import/export; user preference save/load.
- Essential gates (audible result, persistence, undo/dirty state, recovery as applicable): No notes or automation are lost when changing the view/focus. Drum note playback remains MIDI-compatible. View state does not dirty the project. Test preset pitch/name mapping and map fallback. Runtime visual review in OpenTrack required; no acceptance by compilation alone.
- Review owner and milestone stop: self-review implementation, then stop for user review of automation-row density and drum-mode hit placement/presentation.
