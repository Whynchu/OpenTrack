# T088 - Instrument editor access and VST crash report

- Status: in_progress
- Desired outcome: A selected Instrument track exposes a direct command to open its loaded VST3 instrument editor. Opening FX/Channel Settings and opening a VST editor must not crash the app; failures should report a useful error and leave the project usable.
- User report (2026-11-03): While creating an Instrument track with MT Power Drum Kit and trying to open FX, OpenTrack crashed. User also noted there was no way to open the loaded instrument editor.
- User runtime feedback (2026-11-04): On the updated Linux package, MT Power Drum Kit loaded and made sound. The user noticed the instrument input was not registering for Dynamic EQ, editor sizing issues, and playback that felt slow/crackly. The user also specified that instruments need a dedicated named Instrument section/slot as the first item in the track's insert area, with its own behavior separate from ordinary effects. Capture these as follow-up requirements; they are not implemented in this checkpoint.
- Crash evidence: `/home/samuelboxold/.cache/drkonqi/crashes/OpenTrack.aeb6e50e0c2a42be89a7c7c7d7bf2764.1993769.1793752739000000.ini`, 2026-11-03 19:38:59 EST, SIGABRT. The main thread stack is in `rfd::FileDialog::pick_folder` via `OpenTrackApp::ui`; no VST editor thread is present. A later local panic log (21:14 EST, different process) records egui failing because its UI callback did not return while a dialog was open. This confirms a separate blocking-dialog defect, but does not prove it caused the 19:38 abort or the user's FX crash.
- Implementation: Project Inspector now shows a `V` button for a selected Instrument track when an enabled VST3 insert is present. It opens the first enabled VST3 insert through the shared editor host. The request is deferred until after the Project renderer returns. The existing Channel Settings insert eye still opens effect editors. Plugin Information Add Folder/Add Plug-in File now run through `rfd::AsyncFileDialog` on a worker, with results applied on the UI thread.
- MT Power Drum Kit hosting changes: zero-main-input layouts (including auxiliary-only input buses) are accepted; scheduled MIDI note events are sent through a bounded VST3 `IEventList`; multiple main mono/stereo outputs are activated and mixed to stereo. A direct synthetic MIDI probe remained silent, but the user's later actual-project runtime test confirmed the instrument loads and makes sound. Fresh Linux package: `builds/x64/OpenTrack`, SHA-256 `53de2dc75e5d68d2d46e4f9477528957c82f521c30e5eec873a1763845743d06`.
- Architecture boundaries: Keep VST3 instance and editor lifecycle in `vst3_host`; keep UI request in Project Inspector/app state. Do not imply plug-in crash isolation: the current VST3 ABI runs in-process, so a native abort cannot be caught by Rust UI error handling.
