# T053 — Group audio tracks

- Status: editing_tools_accepted_waveform_edge_case_review_pending
- Scope version and requirement IDs: v1; user discussion in this conversation.
- Desired observable outcome: users can create a group audio track, place existing audio tracks/groups inside it, collapse/expand its children, and edit its contents as one surface while retaining separate child tracks and their timing.
- Project-row interaction decision (2026-10-27): grouping is done by dragging one or more selected tracks over a group row. The drop cue is a short accent marker along the lower edge of the group header. Shift-click remains the existing multi-select gesture; dragging any selected row moves the selected tracks together in their existing order. Grouping is not a right-click action. The existing take-lane control position is the Group expand/collapse control and uses a Group-specific stack-and-G SVG; there is no separate chevron. Muted/soloed ancestor state is reflected on descendant M/S controls.
- Follow-up display/configuration changes (2026-10-27): group creation now offers Mono/Stereo and persists the selection on the group track. Mixer M/S buttons display inherited parent-group state as well as local state. The project track-header region is widened from 198 to 264 px, and the group icon uses the same viewBox sizing/placement as the take-lanes icon.
- Group row movement and placement (2026-10-27): moving a group carries all descendants while preserving their internal parent links and order. Reordering a track into a position between group members assigns it to that group. Dragging a group into another group carries its descendants together and respects the two-level nesting limit.
- Collapsed overview (2026-10-27): a collapsed group draws one normalized composite from audio descendants, mono or stereo according to the group channel setting. The current display combines source waveform peak ranges on the project timeline and applies clip fades/gain plus track gain/pan; normalization is based on the visible time range. Inserts, group-bus processing, and phase-accurate sample summing are not yet represented.
- Group editing and routing follow-up (2026-10-27): the collapsed group event surface now drives synchronized split/cut/delete/copy/paste/move/trim and shared fade/gain gestures over descendant audio clips. A group is a playback bus; default child routes feed it and its output feeds Stereo Out, with nested group buses processed before their parent. When tracks leave a group, auto-managed routes return to Stereo Out. Explicit non-default routes are preserved across group changes. The Mixer and Inspector display group names for auto-routes. The lower-zone Sample Editor tab is now labeled Audio Editor.
- User review correction (2026-10-27): the user clarified that a collapsed group is one continuous virtual event spanning its earliest child start to latest child end. Explicit group cuts and boundaries shared across all populated child tracks divide it into selectable pieces; unshared child clip edges remain hidden in the group view. Selecting and moving a piece applies to child clips within that time range. The earlier unconditional highlight of child recordings on collapse is removed. Shared group cuts persist on the group track and move with the selected piece. Project meters use one lane for mono tracks. VST Channel Settings resolves Group IDs to names and lists valid group destinations for every track, including tracks outside that group.
- Drag-preview follow-up (2026-10-27): during a group-piece gesture, the source segment remains visible as a translucent ghost while the candidate composite is redrawn live from the child clips' candidate positions/edits. The group segment hover/drag response explicitly retains the standard arrow cursor. Existing base composite styling is unchanged. This source-level implementation and x64 build are complete; live drag, hit/cursor behavior and visual parity need user review.
- User acceptance (2026-10-27): group editing tools and the drag interaction are accepted as working as intended. Mark editing tools good to go. Leave waveform edge cases for a separate user study at a later time; do not hold editing-tool acceptance on that review.
- Reference evidence: User-specified behavior in conversation; no external reference required.
- Dependencies and decisions needed: The user confirmed two levels maximum (a group may contain groups, but those groups cannot contain groups), one parent per track, preserve child arrangement at grouping time, stereo composite overview for stereo groups and mono overview for mono groups, visual normalization within the group, group mute/solo propagation, and default child routing through the group to Stereo Out while preserving later manual routing changes.
- Code scope and architecture boundaries: `opentrack-core` owns persisted group membership and validation; `opentrack-app` owns project row hierarchy, drag/drop and group editing/overview rendering; `opentrack-audio` owns group bus mixing and effective mute/solo. Avoid callback allocations/blocking and preserve ordinary routing. OPR backward compatibility must be maintained.
- Acceptance checks: (1) create/group/ungroup existing audio tracks without changing their positions; (2) nest one group level and reject deeper nesting/multiple parents; (3) collapse/expand and save/reopen membership; (4) verify group split/cut/copy/paste/move/trim and shared fade/gain gestures apply to descendant clips with common offsets and undo; (5) group mute/solo covers descendants while child solo remains global; (6) verify auto-routing into/out of group, custom route preservation, group-bus processing, and Stereo Out; (7) verify normalized mono/stereo composite waveform and persistence after reopen; (8) confirm Audio Editor label; (9) build the x64 local-ASIO app and exercise in OpenTrack.
- Affected regressions: Project row selection/drag/track controls, take lanes, clip edits/undo, mixer routing, audio mute/solo and output summing, project open/save compatibility.
- Essential gates: Save/reopen preserves membership, channel mode, routing, and edit history semantics. Audio callback remains allocation-free and bounded. Live visual/audio review required; user acceptance pending.
- Review owner and milestone stop: Stop for user review after feature implementation and in-app example-project review. Do not claim waveform fidelity until validated against actual group output.
