# Linux audio real-time scheduling

- Status: review_pending (Linux build, targeted device-curation tests, direct RTKit promotion and denied-promotion fallback verified; opt-in callback timing measured on PipeWire and under a muted synthetic CPU-load comparison; loaded-project/audio-quality review open)
- Scope version and requirement IDs: Linux ALSA audio callback scheduling, first stage `linux-audio-realtime-v1`.
- Desired observable outcome: On Linux builds with the feature enabled, CPAL requests RTKit-backed real-time scheduling for eligible ALSA stream threads. Audio Setup exposes both direct `hw` endpoints and format-converting `plughw` routes where available. Audio continues at normal priority when promotion is denied; the DSP diagnostics distinguish denied promotion from audio xruns and decode RTKit's `SCHED_RESET_ON_FORK` policy modifier correctly.
- Reference evidence: User direction to close the Linux scheduling gap; existing `T058` callback invariants and `audio-xrun-recovery.md`; CPAL 0.18.2 `realtime-dbus` feature and RTKit behavior.
- Dependencies and decisions needed: CPAL `realtime-dbus` requires the system D-Bus development library at build time and an RTKit service/session policy at runtime. Do not require root, alter global limits, or add a privileged helper. Manual Cargo builds opt into `linux-realtime`; the standard Linux packaging script enables it.
- Code scope and architecture boundaries: `opentrack-audio` exports `linux-realtime` to enable CPAL's RTKit feature; `opentrack-app` forwards it. CPAL owns OS thread promotion. ALSA curation retains direct `hw` alongside `plughw`; if no sample rate is explicitly selected, the engine chooses a supported sample format at the device's preferred rate so direct hardware can open. The CPAL worker's scheduler policy is read from `/proc` on the UI thread, masking `SCHED_RESET_ON_FORK` before decoding FIFO/RR; the error callback separately counts `RealtimeDenied`. When `OPENTRACK_REALTIME_DIAGNOSTICS` is enabled, Linux F32/I16/U16 output callbacks now record render duration and callback interval into the existing bounded ring; disabled callbacks do not read the clock. No procfs access or scheduler query runs in the audio callback. No project format changes.
- Acceptance checks: Linux x86_64 `cargo check` with and without feature; run ALSA hardware and server-backed configurations where available; capture whether RT promotion succeeded or was denied; confirm playback continues when denied and xrun counts remain semantically accurate; compare callback timing and dropout behavior at equal device settings.
- Affected regressions: Linux audio startup on systems without RTKit/libdbus, ALSA xrun recovery, diagnostics and default builds, Windows WASAPI/ASIO.
- Essential gates: Runtime RTKit success and denied-policy fallback must be observed on Linux; code compilation alone does not establish scheduling elevation or low-latency stability.
- Review owner and milestone stop: User review after Linux device checks and a before/after callback-load/underrun comparison.
