# T062 - Channel EQ and tonal reference

- Status: active implementation. The existing EQ view has selectable short-spectrum and long-capture tonal-reference analyzer modes.
- User goal: complete and expand OpenTrack's Channel Settings EQ, with a modern parametric workflow and a separate long-window tonal-reference workflow.
- References: Pro-Q 4 and Tonal Balance Control product pages plus the two user screenshots are feature and visual-clarity references. Do not retain or ship their assets, code, names, colors, or target content. Keep the OpenTrack visual identity.
- Architecture: extend `ChannelEqualizer`, its project serialization, Channel Settings controls, `EqualizerControl`, and channel DSP in Rust.

## Product direction checkpoint (2026-10-30)

The existing Channel Settings EQ remains the sole EQ processor and retains its
project persistence. Tonal capture, target comparison and reference import are
functions of its analyzer view. “Separate tonal setting” means a distinct
long-capture analyzer mode with its own controls, not a different EQ setting.

## First acceptance milestone (2026-10-30)

The first acceptance milestone is one polished, persistent EQ experience in
the existing Channel Settings workflow. It includes the 32-band parametric EQ,
short-window spectrum, dynamic EQ, and the separate long-window tonal-reference
mode with capture/import and saved target comparison. These are views and
functions in the same channel workflow. Completion requires the staged
behavior, persistence, audio, visual, and user-review checks below, not just
implementation or compilation.

“Support a lot of Pro-Q features” is a direction for this defined EQ workflow,
not a commitment to reproduce every Pro-Q feature. Matching, phase modes,
spectral dynamics, Mid/Side, extra analysis tools, sketches, masking, MIDI learn,
and analog character are follow-on milestones in the broader EQ goal. Scope each
from the Later enhancements list in its own acceptance packet before
implementation. The tonal-reference display is analysis only: it does not
auto-correct, normalize, or alter the EQ/audio path.

## Intended user experience

Channel Settings remains the EQ entry point. Its graph is the primary editor, with live response and spectrum clarity guided by the supplied references. The responsive spectrum and tonal-reference analysis are two distinct analyzer modes alongside that EQ: the short-window view follows current audio quickly; the tonal view summarizes sustained audio over a longer interval and compares it with a saved or imported target. Switching analyzer mode does not change EQ settings, audio processing, or saved target. Leaving Tonal mode stops active capture and marks the partial capture incomplete. Changing the tonal analysis tap also invalidates the current capture and continuous average. Tonal analysis is measurement and reference, not automatic correction. Both modes are available for tracks, groups and Stereo Out.


The contextual editor contains direct frequency, gain, Q, shape/slope, enable, solo and (in the dynamic milestone) threshold/range/attack/release controls. Parameter knobs use a generic SSL-like shape and tactile feel, with grayscale surfaces and original OpenTrack artwork. Channel color from the existing Channel Settings color coding identifies bands, nodes and curve accents; the knobs themselves remain grayscale. The reference is for knob form and feel only.

The graph uses logarithmic frequency and readable dB axes. Distinct, labeled visual encodings distinguish aggregate EQ response, short-window input spectrum, post-EQ spectrum, long-window average and target range/difference. Selected controls remain legible and avoid obscuring their node. Preserve clarity at high DPI and smaller window sizes; verify overlapping traces, flat response, silence and dense bands in the running app.

## Feature scope

### Core EQ and responsive analyzer

- Expand the current four-band EQ to a useful multiband parametric EQ, starting with eight bands. Shapes: bell, notch, low/high shelf and low/high pass, with defined slope choices and Q.
- Provide up to 32 persistent bands, each independently created, selected and removed through the strip or graph. Right-click removes a band; double-clicking empty graph creates a bell band at that frequency/gain; `+` creates the next band at a useful default frequency. Drag nodes to change frequency and gain; contextual controls edit frequency, gain, Q and shape. Provide per-band solo audition and global bypass. Solo is a transient frequency-isolated band-pass centered on the selected band's frequency/Q, smoothed over 5 ms, and does not dirty project state. It is available for tracks/groups and Stereo Out; input bus audition is disabled. Define hit targets and avoid accidental band changes.
- Keep EQ parameter edits live and smoothed in the current audio engine. Parameter changes must not rebuild the whole playback plan or allocate/wait inside the callback. Establish stable IDs for future automation; automation lanes are not implied unless the app already supports them.
- Short-window analyzer shows pre-EQ and post-EQ spectrum independently from the EQ response curve, with adjustable averaging/speed (using the persisted Preferences > Metering release-smoothing control), resolution, range, tilt, freeze and peak hold. Use bounded callback capture and calculate FFT/display data outside the callback.
- Extend project state compatibly. Existing OPR/OTP/RWP projects preserve all current EQ values and gain new bands with neutral disabled defaults. Saving, closing and reopening restores band settings and bypass. View/hover/selection state stays transient unless existing workspace persistence conventions specify otherwise.
- Initial support: mono and stereo channel paths. Define behavior for groups and Stereo Out. Mid/Side and Left/Right processing are a later scoped enhancement.

### Dynamic EQ

- Add dynamic bell and shelf behavior per eligible band: detector threshold, signed gain range, attack/release and internal band-filtered detection. Show static response, allowed gain range and actual dynamic movement distinctly.
- Define stereo linking, detector behavior, knee, smoothing and bounded CPU cost. Exercise thresholds with generated signals and real audio, listen for artifacts, and confirm low-buffer playback stability.
- Spectral dynamics (frequency-selective gain within a band) is a separate research milestone; do not present ordinary dynamic EQ as spectral dynamics.

### Tonal Balance and reference capture

- This is a separate long-window analysis from the responsive EQ spectrum. Default analysis tap is post-EQ; offer pre-EQ comparison within the tonal-analysis controls. Label the tap because it is not necessarily the final channel or mix output. Tap selection changes what is measured, never which EQ processes audio.
- Implement a documented spectral power accumulation, frequency weighting/smoothing and normalization method. Reference and measured signal use matching analysis settings. Tonal comparison is display-only and never applies normalization gain to audio.
- Show broad frequency regions, a fine frequency target envelope/range and a normalized difference view. Label the target and current average distinctly from actual EQ gain. The first target envelope uses a fixed ±3 dB guidance range around the saved target curve; it is not a pass/fail result or an automatic correction.
- Continuous mode maintains a weighted average with a selectable 10/30/60/120-second time constant, Hold/Resume, Reset, elapsed valid-signal time and a warm-up indicator (settled after three time constants). It updates only from the selected channel in Tonal mode. Explicit capture has Start/Stop, elapsed valid-audio time, Reset and Save Target; Hold affects only the continuous average. Silence below a documented gate does not dilute either analysis; all-silent or too-short captures cannot create a target.
- Import reference audio and capture from the selected channel tap. Analyze/import off the audio callback, cancellably, and reject stale results. Stop/seek pauses explicit capture and marks it incomplete; reopen never resumes capture automatically. Sample-rate or channel-layout change invalidates capture and marks existing results incomplete until Reset or a new capture.
- Store a compact saved target, analysis version/settings and provenance in the channel EQ project state so saved projects do not depend on the original reference file. WAV import stores only the target profile, source basename, duration, rate and analysis settings; it does not retain or relink the original media. Reusable library targets may be stored in the user library and copied into project state when selected. Missing/corrupt imports must not affect playback. Define size limits and migration before implementation.
- Target blending and independently sourced genre targets are later work; do not copy another product's target collection.

### Later enhancements

EQ matching with preview and explicit apply; linear/minimum/natural phase modes with latency reporting; spectral dynamics; extra vocal/dynamics/stereo-width/low-end meters; Mid/Side and Left/Right; EQ sketch, spectrum grab, masking views, MIDI learn and analog character. Each requires a separate behavior, DSP, cost and acceptance packet. No proprietary algorithm or performance claim is assumed from a feature label.

## Persistence, safety and acceptance

- Preserve existing project EQ sound during schema migration. Test old and new projects, undo/redo, dirty state, save/reopen and removal/reset behavior.
- Audio callbacks perform no file access, UI work, unbounded allocation or waiting. Smooth parameter changes, protect against non-finite values and document CPU/memory cost. Bypass and channel mute/solo behave consistently with current strip processing.
- Handle silence, seek/stop, device/sample-rate changes, mono/stereo, missing reference data and cancellation. Analysis is observational and cannot dirty EQ settings unless the user saves/changes persistent target data.
- Each milestone records code, automated behavior checks, live OpenTrack behavior, audible quality, build identity and user acceptance separately. Build success alone is not acceptance. Visual and listening review happens in the running app; user-supplied screenshots remain task inputs and are not archived by default.

## Staged delivery and review order

1. **Core EQ acceptance:** consolidate the existing `ChannelEqualizer` schema/DSP, graph, band strip, contextual grayscale knobs and short-window analyzer. Verify live edits, audible response, compatibility, save/reopen, callback safety, and visual clarity in the running application. This is the first review gate.
2. **Dynamic EQ acceptance:** review the already-started dynamic controls and processing as an extension of the same EQ. Confirm signal behavior, parameter persistence, CPU cost, artifacts and listening quality before treating it as complete.
3. **Tonal reference acceptance:** treat short spectrum and long capture as selectable analyzer modes of the same EQ view. Verify capture/import, normalized comparison, signal tap, silence/discontinuity handling, cancellation, save/reopen and real-mix usability. The long-capture mode measures and compares; it does not add another EQ or change the audio path.
4. **Advanced features:** continue the broader EQ goal through separately scoped and reviewed milestones from the Later enhancements list. They follow acceptance of the core, dynamic, and tonal-reference stages above.

The implementation order has already crossed these boundaries: parts of dynamic EQ and tonal reference exist before the core review gate. The remaining work follows the acceptance order above so each layer is reviewed against the intended Channel Settings workflow.
