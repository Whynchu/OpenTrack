## Coverage and explicit limits

Inspected app startup, app window/dialog function list, main menu entry points, project lifecycle dialogs, key-command/workspace windows, principal editor windows and separate audio configuration/preferences/transport/media modules. This is a source window/dialog register, not a complete button/value-field audit of every window. Control-level selectors are in `audit-comboboxes.md` and `audit-custom-selectors.md`; main and context menus are in `audit-menus.md`. Generated project tracks, devices, plugins, key commands, workspace rows and file-picker contents are dynamic families, not fixed source entries.

No app source changed during this audit. The app-level evidence does not establish runtime visibility, native dialog behavior, hardware/device availability, plug-in compatibility, audio behavior, persistence across restart for every transient preference, or user acceptance. Several dialogs use custom `dismiss_window_on_outside_click` and parent-state guards; dismissal should be verified at runtime for modality and focus ownership. Line references in this document are approximate function starts where abbreviated with an ellipsis; use the named function/section to inspect full bodies.
