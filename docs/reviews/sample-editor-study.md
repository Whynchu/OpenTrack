## Permanent architectural/style direction

User explicitly prefers the Cubase Sample Editor organization/style to PitchNet/HachiTune. All first-party application, editing, analysis orchestration, segmentation and rendering stay Rust. Keep original OpenTrack colors. Research neural detectors separately from synthesis; neural detection does not require adopting a neural vocoder or replacing our UI/application with C++/JUCE.

## Bounded implementation queue

1. **T023 editing foundation (current review slice):** lower-zone tabs; audio-event editor target; waveform overview/ruler/range/zoom/pan; existing position/source trim/gain/fade edits through shared core/history; held toolbox, common snap scissors, two-event linear overlap crossfade. Preserve media and source fades, undo/redo and older projects. Pitch/time controls disabled and explained. Review before next substantial editor milestone.
2. **Pitch-analysis foundation:** Rust worker interface accepting source fingerprint/channel policy/window/analysis version. Return timestamped F0, confidence/voicing, never pretend unvoiced audio is pitched. Baseline with calibrated synthetic tones, vibrato, glides, silence/noise and a consented monophonic vocal fixture. Candidate neural inference adapter evaluated separately, using CPU fallback; channel selection and mono/stereo mapping explicit. Progress/cancellation/stale source-result rejection and bounded caches required. Start with single melodic voice, not a promised polyphonic separator.
3. **Musical segmentation and pitch commands:** stable note IDs separate from measured contour; manual split/join, movable left/right recognition boundaries, voiced/unvoiced exclusions and reversible analysis reset. Pitch quantize/straighten/transpose/cent edits stored as intent, plus preserved original contour. Cubase-style keyboard axis and region/trace overlay. Controls become operational with audible synthesis, not just moving rectangles.
4. **Audible pitch/time rendering:** source-to-project monotonic piecewise warp map, segment pitch offsets and local boundary anchors; independent duration/pitch where specified. Worker-produced immutable audio/versioned cache, existing render publication, no inference/allocation/file I/O in callback. Preserve timing, source references and stereo phase; test transitions/seams, formants/transients and stretch bounds. Absorb/ripple behaviors require explicit evidence/design rather than copying names. Audition/bypass, original/processed comparison and glitch-free updates belong here.
5. **Optional neural path and polish:** benchmark detector accuracy and neural versus conventional synthesis independently. Measure latency, memory, CPU/GPU load, failure/cancel/offline behavior and artifact quality. Add opt-in models only after capability/license/resource decisions. Do not make model downloads, GPU availability or internet access prerequisites for ordinary waveform editing.

## Measurement contract

Track editing foundation, detection, note segmentation, audible pitch, time warp, persistence/recovery, real-time stability and visual parity as separate requirements. No arbitrary whole-DAW percentage. Synthetic F0 metrics: voiced/unvoiced errors, cents error and octave mistakes; timings: onset/offset/source-map error; audio: identity/bypass, pitch accuracy, duration, seams, stereo coherence, peak/clipping and null tests where identity is expected. Vocal quality needs documented listening comparisons, not FFT-only assertions. Report dataset/source identity and parameter settings; establish numerical thresholds before evaluating candidates. Unknown reference interactions and hidden controls stay unknown.

Required scenarios: double-click/tabs/toolbox/cut/X; undo/redo/save/reopen exact source edits; note detection/cancel/resume; manually repair segmentation; pitch and local time edits produce correct audio; switch tabs/projects during background jobs without stale publication; missing source/model recovery; no dirty prompts from selection/tab switching. Current first slice only establishes the first scenario foundations; no neural or full Sample Editor parity accepted.

## On-demand Pitch & Time direction (2026-10-25)

User clicks Pitch & Time on the current audio event to begin analysis of that event's source range. Import, playback, project open and ordinary Sample Editor access do not schedule pitch analysis. First activation exposes progress/cancel, then an editable detected-note view when real results arrive. Subsequent activation reuses valid results. Save/reopen restores the analyzed state and musical edits. Store durable edit intent in the project; managed analysis metadata is keyed by source identity, analyzed source range and algorithm/model version. Source replacement or incompatible analysis versions invalidate affected results and offer explicit re-analysis; canceled/stale jobs cannot publish over newer edits. Waveform generation/live channel-spectrum analysis remain independent. Pitch analysis and audible pitch/time correction are still unimplemented; the disabled placeholder must not imply otherwise.
