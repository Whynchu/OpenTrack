### Empty-project shell

When no project, only File, Edit, Project, Audio, Devices, MIDI, Scores, Media, Transport, Window, Help remain in compact branch (`show_empty_project_menu`, app.rs:8537-8595). File has active New Project/Open/Quit; Save/Save As disabled. Edit has disabled Undo/Redo and active Key Commands. Project and Audio contain informational disabled “No project is open.” Devices has active Device Setup and disabled VST Connections. MIDI/Scores/Media/Transport/Window each show the same informational empty-state row. Help exposes active About. These shell rows are state explanations, not missing handlers.

## Coverage ledger and unresolved inspection

Inspected source entry points: `app.rs` main/empty menu, ruler/diagnostic/MIDI context closures, Channel Settings top-level context, insert picker and EQ/routing/preset popup anchors; `project_controls.rs` background/track/color menus; `mixer.rs` insert/send context; `transport_panel.rs` context; `channel_settings.rs` dynamic insert/filter/routing/send/preset menus; `project_inspector.rs` routing popup. Every main-menu label found in `show_menu` and `show_empty_project_menu` is registered above, including disabled rows and generated MIDI/workspace families.

No dedicated audio-event context menu exists among the `context_menu` call sites found in `opentrack-app`; event operations are reachable through Edit menu and editor/tool routes. MediaBay currently has menu navigation to three tab indexes; its internal selectors are outside menu scope and covered in selector audits. Counts are grouped by path/family rather than individual leaf rows to retain readable paths; the rows enumerate the leaves explicitly. Runtime visibility, actual click success, persistence across restart, and audio/device behavior are unverified.
