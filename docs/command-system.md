# Command and keyboard model

The Windows default command list transcribed from the local Operation Manual is in `reference-keymap-windows.csv` (printed pages 484-486). `opentrack-core::commands::KeymapProfile::windows_reference_default` parses the checked-in table into 152 stable command definitions and 158 bindings, expanding the manual's digit ranges. The app resolves these bindings through the shared context-aware keymap before dispatching commands.

The manual describes key assignments as global preferences that can be saved separately as XML presets. A command may have multiple shortcuts, conflicts can be reassigned, and macros can combine commands. Tool modifier keys are configured separately. These behaviors imply that commands and shortcuts need separate models rather than hard-coded event handlers.

The default list contains both `Open/Close Editor` on Return and `Play` on Enter. The editor command is scoped to the `editor` context, while Play remains the application fallback; OpenTrack- activates that context while its MIDI Editor is open. Ctrl+E opens the selected MIDI part in the editor. Numpad keys must stay distinct from the top-row digits. The Windows subclass captures the application's key-down events and preserves keypad digits and operators as distinct physical keys; other platforms use egui's logical key events.

When the Virtual Keyboard is open, the manual says ordinary commands are suppressed except for Save, Record, Start/Stop Playback, Jump to Left Locator, Delete, Cycle, Transport Panel, and Virtual Keyboard visibility. The app should model this as an input-capture mode with an explicit command allowlist.

`opentrack-core::commands` provides stable command IDs, built-in and macro definitions, platform-independent key chords, context scopes, conflict discovery, and context-first resolution. Ambiguous assignments are reported as conflicts instead of silently selecting the first matching command. Letter keys are normalized through the `KeyChord` constructor, and numpad keys have distinct variants. Ctrl+Z and Ctrl+Shift+Z dispatch through the editable map; Ctrl+Y remains an application fallback for redo. The app also dispatches project file commands, core panel visibility, transport controls, track mute/solo/Solo Defeat/record-arm, workspace actions, tool selection, Undo/Redo, and MIDI editor open/close. Ctrl-clicking a Solo button clears other solo states, and Alt-click toggles Solo Defeat. Reference commands without app implementations display an unavailable status. The categorized Edit > Key Commands window lets users add, change, or remove shortcuts, confirms conflicting assignments, and restores the reference defaults. Assignments persist in eframe application storage; XML preset import/export, macros, and broader project editing remain pending.

The app now loads all manual bindings, including F2 (Transport Panel), F3 (Mixer), F5 (MediaBay), F6 (Loop Browser), F7 (Sound Browser), Enter (Play), Space (Start/Stop), and the workspace keypad commands. The manual also assigns Numpad Minus to both Forward and Rewind; the resolver reports that default conflict, and the Key Commands window lets the user choose an assignment. Many mapped commands are catalogued but still need their corresponding editor, marker, zoom, or project-editing behavior implemented.
