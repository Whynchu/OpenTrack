# Native project format

The app's native files use the OPR extension and UTF-8 JSON. They are independent of CPR files.

New files use the `opentrack-project` format marker. The reader also accepts the earlier native marker so existing projects remain openable; reading an older project normalizes it to the OpenTrack marker for its next save. It accepts `.opr`, `.otp`, and `.rwp` through the existing project reader.

## Current format fields

- The format marker identifies the document.
- The version is the native format version. The app writes version 20 and migrates versions 1 through 19 on open. Version 18 added the managed-project-folder marker. Version 19 corrects legacy mono Audio tracks that stored Stereo In as their default to Left - Stereo In. Missing rate/encoding fields preserve 44.1 kHz and 32-bit float; newly created projects default to 48 kHz and 24-bit PCM. Existing project rate and recording format remain editable in Project Setup.
- Version 20 adds independent `input_channel` and `output_channel` bus-strip settings (gain, balance, polarity, EQ, built-in inserts, bypass and mute). Legacy projects default both to unity with processing inactive. Reserved bus identities do not occupy arrange lanes or consume track IDs. Files validate bus state before replacing the open project.
- Managed projects keep the `.opr` at the project-folder root and create `Audio/Recordings`, `Audio/Imports`, and `Metadata`. Recording takes use `Audio/Recordings`; newly imported external WAV files are copied to `Audio/Imports`. `Metadata/Undo` temporarily holds recovery for undone recordings. History and growing waveform snapshots are session-only; completed waveform data is regenerated from audio assets.
- The project stores the project name, track IDs and kinds, mute/solo/Solo Defeat/record-arm state, linear channel gain, four-band EQ settings, ordered insert-effect settings, tempo, time signature, cycle locator positions in quarter-note beats, Instrument track waveform, selected track, and ID counters. Audio tracks also store clips with a display name, external WAV path, timeline start in beats, source duration, and clip gain. MIDI parts store note and controller events (including MIDI channel) relative to each part's start.
- The workspace state stores project workspace names, lock flags, active index, optional global-preset origin, project-specific preset snapshots, and saved window snapshots. Main-window snapshots contain an egui_dock layout in their versioned view-state payload. A project-specific MIDI Editor snapshot stores its open/closed state and logical position and size. Global preset definitions and the auto-instantiate preference live in application settings.
- The live dock state stores the current visible layout separately, so changes to a locked workspace can be restored when reopening without replacing its recall snapshot.
- The show_transport, selected_media, and cycle fields store the visible transport panel, MediaBay category, and cycle setting.

Playback, active recording, the moving transport position, and undo/redo history are session state and are not restored from a project file. WAV media is not embedded: the project stores source paths. New external WAV imports are copied into `Audio/Imports`; recordings are created in `Audio/Recordings`. Older linked media is not copied during folder migration, and media paths remain absolute, so moving a project may require relinking. Missing or unreadable sources leave the project open and are reported in the status line. Use **File → Relink Unavailable Audio** to choose a replacement WAV; all clips sharing that source path are updated together, and the path change can be undone. MIDI and Instrument tracks store arrangeable parts with beat-based starts and lengths; each part stores note and controller events at positions relative to its start. Project-wide part, note, and controller-event IDs and the selected part are persisted. The version 5 migration wraps each track's direct note list in a part starting at beat zero, retaining note positions and IDs. New EQ, insert, MIDI, cycle-locator, instrument waveform, controller, MIDI-channel, Solo Defeat, workspace preset-origin, and managed-folder fields use serde defaults so older projects continue to load. Arrange track heights are stored in the main-window view-state payload. The Cycle enable flag is stored as top-level project UI state; locator positions and selected built-in voice are project data. The built-in oscillators are starter instruments, not bundled plug-in rewrites. Automation, monitor-aware restoration of floating windows, and general third-party plug-in/editor state are not implemented yet.

## Read and save behavior

The reader caps files at 64 MiB, checks the format marker and version, validates project ranges and IDs, and requires the project pane to be present in the saved dock state. It builds and validates the complete document before replacing the open project, so a failed open leaves the current project intact.

Saving serializes to a temporary file in the destination directory, flushes it, then replaces the destination. Windows uses MoveFileExW with replace-existing and write-through flags through windows-sys; this is the app's explicit Win32 FFI boundary. On Unix, the app uses same-directory rename and syncs the parent directory.

Version 1 files are upgraded to one unlocked workspace named Arrangement; versions 2 through 19 migrate to version 20. Version 5 note events are retained by wrapping them in a part. Missing EQ and insert fields deserialize to neutral defaults, and missing MIDI-part, note, controller-event, MIDI-channel, ID, cycle-locator, instrument-waveform, Solo Defeat, workspace preset-origin, and managed-folder fields receive defaults. The app currently supports up to nine named workspaces per project, switching, lock/recall, keyboard shortcuts, and an organizer for names, order, and explicit shortcut IDs. The organizer stores project presets and can copy global presets into them. Global presets and the auto-instantiate preference are saved in application settings; instantiated preset origins are stored with the project. Monitor-aware floating-window restoration remains future work.
