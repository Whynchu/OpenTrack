# Native project format

The app's native files use the OPR extension and UTF-8 JSON. They are independent of CPR files. The current document describes source behavior; runtime and user acceptance are tracked separately in `docs/workflow/current.md`.

New files use the `opentrack-project` format marker. The reader also accepts the earlier native marker so existing projects remain openable; reading an older project normalizes it to the OpenTrack marker for its next save. It accepts `.opr`, `.otp`, and `.rwp` through the existing project reader.

## Current format fields

- The format marker identifies the document.
- The version is the native format version. The app writes version 46 and migrates versions 1 through 45 on open. Earlier OpenTrack versions cannot open a version 46 file, protecting data the format gained after their release from being silently discarded. Version 18 added the managed-project-folder marker. Version 19 corrects legacy mono Audio tracks that stored Stereo In as their default to Left - Stereo In. Missing rate/encoding fields preserve 44.1 kHz and 32-bit float; newly created projects default to 48 kHz and 24-bit PCM. Existing project rate and recording format remain editable in Project Setup.
- Version 46 adds stable insert-instance IDs and the next-ID counter, plus VST3 `plugin_parameter(insert_id, parameter_id)` lanes, device-bus volume/pan/mute lanes, and FX channel support for channel and plug-in automation. Version 45 added `track_pan`, `track_mute`, and slot-addressed `send_level`/`send_pan` alongside `track_volume`. Pan points use -1..=1 and interpolate linearly; mute points use 0 or 1 and step at the point beat; send level points use linear gain 0..=3.981072. Older files receive insert IDs during migration and their existing automation fields retain defaults.
- Version 43 adds per-part `chord_symbols` (beat + short text) produced by Scores > Make Chord Symbols from major/minor/diminished/augmented triads. Symbols are presentation only and older parts load with none.
- Version 42 adds an optional per-note `group` id: notes sharing an id are bracketed together in the score. Grouping is score presentation only; older notes load ungrouped.
- Version 41 adds a per-note `slur_to_next` flag: the score draws a slur from the note to the next note in the part. The last note cannot hold one, and older notes load without slurs.
- Version 40 adds a per-note `grace` flag: grace notes draw as smaller heads with a slash and still take their written length in playback. Older notes load as ordinary notes.
- Version 39 adds per-note score flags (`hidden`, `flipped`): hidden notes keep sounding but draw as a staff placeholder, flipped notes draw their stems in the opposite direction. Older notes default to visible and unflipped, and both flags are score presentation only.
- Version 38 adds per-event offline processing chains (`offline_chain`): an ordered list of first-party processors (gain, normalize, reverse, remove DC offset, stereo flip, resample, time stretch) bounded to eight entries, with parameters validated on load. The chain is intent only; audio is unchanged until the chain is applied. Older events load with no chain.
- Version 37 adds the arranger sections and sequence.
- Version 36 adds track folder hierarchy.
- Version 35 adds FX channel identity.
- Version 34 adds the project drum map.
- Version 33 adds `pool_record_folder`: a project-relative folder where new pool files (imports, bounces and processed copies) are written, defaulting to `Audio/Imports`. Only relative paths inside the project are accepted, so a project never writes outside its own tree and stays portable; recording takes are unaffected and stay in `Audio/Recordings`. Older projects load with the default.
- Version 32 adds timeline regions (`regions`, with `next_region_id`): named start/end ranges, ordered by start, bounded to 1,024 per project with 96-character names. Regions are navigation and organisation only — they hold no media and do not change playback on their own — and insert-silence and whole-project cut/delete move them with the timeline. Older projects load with no regions.
- Version 31 adds Media Pool folders (`media_folders`): up to 32 named folders plus a source-to-folder assignment map. Folders are organisation only — the pool still lists every source, unfiled sources stay in the root, and creating, renaming or deleting a folder never touches media or events. Older projects load with no folders. A version-30 file therefore opens unchanged, while an older build refuses a version-31 file rather than dropping the folders.
- Version 30 adds the project timecode offset (`timecode_offset_seconds`, seconds, bounded to 99:59:59). Older projects load at zero, so timecode continues to start at 00:00:00 at beat zero; Set Timecode at Cursor changes the offset and the timecode ruler formats show it.
- Version 29 adds optional fixed marker slots (`slot`, 1-9) so the numeric shortcuts address markers; the value is omitted for ordinary markers, older projects load with no slots, and duplicate or out-of-range slots are rejected.
- Version 28 adds project markers (`markers`, `next_marker_id`), loop-recording take groups (`take_group`, `take_active`, `next_take_group`), the per-track monitoring mode (`monitor_mode`), and the project notepad (`notepad`). Older versions migrate with no markers or takes, monitoring Off, and an empty notepad; a project that stored the legacy `monitor` boolean as on migrates to monitoring On. The version bump means an OpenTrack build that predates these fields refuses the file instead of opening it and silently dropping them on the next save.
- Version 27 adds optional track-volume automation lanes and bounded, validated beat/gain points. Missing lanes default to empty. Read playback, point editing and live write capture for track volume are implemented.
- Versions 25 and 26 add persisted pitch/time analysis and editable note intent, with defaults for older files.
- Version 24 adds a persistent `media_pool` of source paths. Deleted arrange events/rows can retain media without live clips; legacy loads populate the pool from existing clips without rewriting their source files. Explicit Shift+Delete removes unshared paths from the pool through session undo recovery, never by a bare unlink.
- Version 23 adds optional source-anchored fade lineage (`source_fades`) so cutting inside existing fades preserves exact audio without rewriting source WAVs. Older files default to an empty list. Each event retains at most32 validated entries. New local fades multiply inherited fades; undo restores the original unsplit event. Selection/editor tabs are transient.
- Version 22 permits channel gains through 2.0 linear (about +6 dB) for track/device-bus headroom. Existing gain values, including legacy values below the new -30 dB fader floor, are preserved on open. Event gain remains separate.
- Version 21 adds non-destructive event source offsets and fade-in/out durations; absent fields default to zero. Event gain allows up to 4.0 linear amplitude (about +12 dB). Editing preserves source WAVs. Selection/drag previews are transient.
- Version 20 adds independent `input_channel` and `output_channel` bus-strip settings (gain, balance, polarity, EQ, built-in inserts, bypass and mute). Legacy projects default both to unity with processing inactive. Reserved bus identities do not occupy arrange lanes or consume track IDs. Files validate bus state before replacing the open project.
- Managed projects keep the `.opr` at the project-folder root and create `Audio/Recordings`, `Audio/Imports`, and `Metadata`. Recording takes use `Audio/Recordings`; newly imported external WAV files are copied to `Audio/Imports`. `Metadata/Undo` temporarily holds recovery for undone recordings. History and growing waveform snapshots are session-only; completed waveform data is regenerated from audio assets.
- The project stores the project name, track IDs and kinds, mute/solo/Solo Defeat/record-arm state, linear channel gain, four-band EQ settings, ordered insert-effect settings, tempo, time signature, cycle locator positions in quarter-note beats, Instrument track waveform, selected track, and ID counters. Audio tracks also store clips with a display name, external WAV path, timeline start in beats, source duration, and clip gain. MIDI parts store note and controller events (including MIDI channel) relative to each part's start.
- The workspace state stores project workspace names, lock flags, active index, optional global-preset origin, project-specific preset snapshots, and saved window snapshots. Main-window snapshots contain an egui_dock layout in their versioned view-state payload. A project-specific MIDI Editor snapshot stores its open/closed state and logical position and size. Global preset definitions and the auto-instantiate preference live in application settings.
- The live dock state stores the current visible layout separately, so changes to a locked workspace can be restored when reopening without replacing its recall snapshot.
- The show_transport, selected_media, and cycle fields store the visible transport panel, MediaBay category, and cycle setting.

Playback, active recording, the moving transport position, and undo/redo history are session state and are not restored from a project file. WAV media is not embedded: the project stores source paths. New external WAV imports are copied into `Audio/Imports`; recordings are created in `Audio/Recordings`. Older linked media is not copied during folder migration, and media paths remain absolute, so moving a project may require relinking. Missing or unreadable sources leave the project open and are reported in the status line. Use **File → Relink Unavailable Audio** to choose a replacement WAV; all clips sharing that source path are updated together, and the path change can be undone. MIDI and Instrument tracks store arrangeable parts with beat-based starts and lengths; each part stores note and controller events at positions relative to its start. Project-wide part, note, and controller-event IDs and the selected part are persisted. The version 5 migration wraps each track's direct note list in a part starting at beat zero, retaining note positions and IDs. New EQ, insert, MIDI, cycle-locator, instrument waveform, controller, MIDI-channel, Solo Defeat, workspace preset-origin, and managed-folder fields use serde defaults so older projects continue to load. Version 46 assigns stable IDs to inserts while migrating older projects; these IDs keep plug-in parameter automation attached through rack reorder. Arrange track heights are stored in the main-window view-state payload. The Cycle enable flag is stored as top-level project UI state; locator positions and selected built-in voice are project data. The built-in oscillators are starter instruments, not bundled plug-in rewrites. Automation lanes store parameter intent, including hosted VST3 parameter IDs; missing plug-ins leave those lanes unresolved rather than silently attaching them to another insert. Monitor-aware restoration of floating windows and general third-party plug-in/editor state also remain incomplete.

## Read and save behavior

The reader caps files at 64 MiB, checks the format marker and version, validates project ranges and IDs, and requires the project pane to be present in the saved dock state. It builds and validates the complete document before replacing the open project, so a failed open leaves the current project intact.

Saving serializes to a temporary file in the destination directory, flushes it, then replaces the destination. Windows uses MoveFileExW with replace-existing and write-through flags through windows-sys; this is the app's explicit Win32 FFI boundary. On Unix, the app uses same-directory rename and syncs the parent directory.

Version 1 files are upgraded to one unlocked workspace named Arrangement; versions 2 through 45 migrate to version 46. Version 5 note events are retained by wrapping them in a part. Missing EQ and insert fields deserialize to neutral defaults; missing insert IDs are assigned on load/save. Missing MIDI-part, note, controller-event, MIDI-channel, ID, cycle-locator, instrument-waveform, Solo Defeat, workspace preset-origin, managed-folder and drum-map fields receive defaults. The app currently supports up to nine named workspaces per project, switching, lock/recall, keyboard shortcuts, and an organizer for names, order, and explicit shortcut IDs. The organizer stores project presets and can copy global presets into them. Global presets and the auto-instantiate preference are saved in application settings; instantiated preset origins are stored with the project. Monitor-aware floating-window restoration remains future work.
