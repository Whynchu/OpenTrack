# Native project format

The app's native files use the RWP extension and UTF-8 JSON. They are independent of Cubase's CPR format.

The serialized format marker remains rust-audio-workstation from the initial prototype so existing version 1 through 3 files continue to open after the product rename. It is a file-format identifier, not the OpenTrack- product name. Changing it requires an explicit migration.

## Current format fields

- The format marker identifies the document.
- The version is the native format version. The app writes version 14 and migrates versions 1 through 13 on open. Version 4 added channel EQ and insert-effect state; version 5 added direct-track MIDI notes; version 6 stores those events inside arrangeable MIDI parts; version 7 adds persisted cycle locator positions; version 8 adds the selected built-in instrument waveform; version 9 adds part-relative MIDI controller events and their project-wide ID counter; version 10 adds the OpenTrack- Compressor insert type; version 11 adds a MIDI channel to each note; version 12 adds a MIDI channel to each controller event; version 13 records the source global preset for auto-instantiated workspaces; version 14 adds persisted Solo Defeat. Older notes and controller events default to channel 0, and older workspaces have no preset source.
- The project stores the project name, track IDs and kinds, mute/solo/Solo Defeat/record-arm state, linear channel gain, four-band EQ settings, ordered insert-effect settings, tempo, time signature, cycle locator positions in quarter-note beats, Instrument track waveform, selected track, and ID counters. Audio tracks also store clips with a display name, external WAV path, timeline start in beats, source duration, and clip gain. MIDI parts store note and controller events (including MIDI channel) relative to each part's start.
- The workspace state stores project workspace names, lock flags, active index, optional global-preset origin, project-specific preset snapshots, and saved window snapshots. Main-window snapshots contain an egui_dock layout in their versioned view-state payload. A project-specific MIDI Editor snapshot stores its open/closed state and logical position and size. Global preset definitions and the auto-instantiate preference live in application settings.
- The live dock state stores the current visible layout separately, so changes to a locked workspace can be restored when reopening without replacing its recall snapshot.
- The show_transport, selected_media, and cycle fields store the visible transport panel, MediaBay category, and cycle setting.

Playback, active recording, the moving transport position, and undo/redo history are session state and are not restored from a project file. A completed recording is an external WAV clip whose path is saved with the project; WAV media is not embedded. Missing or unreadable sources leave the project open and are reported in the status line. Use **File → Relink Unavailable Audio** to choose a replacement WAV; all clips sharing that source path are updated together, and the path change can be undone. MIDI and Instrument tracks store arrangeable parts with beat-based starts and lengths; each part stores note and controller events at positions relative to its start. Project-wide part, note, and controller-event IDs and the selected part are persisted. The version 5 migration wraps each track's direct note list in a part starting at beat zero, retaining note positions and IDs. New EQ, insert, MIDI, cycle-locator, instrument waveform, controller, MIDI-channel, Solo Defeat, and workspace preset-origin fields use serde defaults so older version 1 through 13 projects continue to load. Arrange track heights are stored in the main-window view-state payload. The Cycle enable flag is stored as top-level project UI state; locator positions and selected built-in voice are project data. The built-in oscillators are starter instruments, not Cubase instrument rewrites. Automation, monitor-aware restoration of floating windows, and general third-party plug-in/editor state are not implemented yet.

## Read and save behavior

The reader caps files at 64 MiB, checks the format marker and version, validates project ranges and IDs, and requires the project pane to be present in the saved dock state. It builds and validates the complete document before replacing the open project, so a failed open leaves the current project intact.

Saving serializes to a temporary file in the destination directory, flushes it, then replaces the destination. Windows uses MoveFileExW with replace-existing and write-through flags through windows-sys; this is the app's explicit Win32 FFI boundary. On Unix, the app uses same-directory rename and syncs the parent directory.

Version 1 files are upgraded to one unlocked workspace named Arrangement; versions 2 through 13 migrate to version 14. Version 5 note events are retained by wrapping them in a part. Missing EQ and insert fields deserialize to neutral defaults, and missing MIDI-part, note, controller-event, MIDI-channel, ID, cycle-locator, and instrument-waveform fields default to empty parts, channel 0, initial counters, a 0–16 beat loop, and a sine voice; missing Solo Defeat defaults to false. The app currently supports up to nine named workspaces per project, switching, lock/recall, keyboard shortcuts, and an organizer for names, order, and explicit shortcut IDs. The organizer stores project presets and can copy global presets into them. Global presets and the auto-instantiate preference are saved in application settings; instantiated preset origins are stored with the project. Monitor-aware floating-window restoration remains future work.
